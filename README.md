# Web Security Tech Talk

Локальная платформа для доклада «Уязвимости SPA: от фронтенда до бэкенда».
Основа содержания: `Cybersecurity.pptx`, 17 слайдов и 12 тем. Порядок тем,
сопоставление с кодом и замечания к материалам: [программа доклада](docs/talk-scope.md).

## Запуск

Нужны Node.js 24 (см. `.nvmrc`) и pnpm 9.15.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

- Доклад: <http://127.0.0.1:3000/talk>
- Введение: <http://127.0.0.1:3000/talk/intro/0>
- XSS в комментариях: <http://127.0.0.1:3000/site/comments>
- CSRF в профиле доставки: <http://127.0.0.1:3000/site/delivery>
- Уязвимая зависимость в карточке товара: <http://127.0.0.1:3000/site/product>
- Страница учебной акции: <http://127.0.0.1:3001/offer>

`pnpm dev` запускает сайт и отдельный статический сервер акции. Если сайт уже
работает отдельно, сервер акции можно запустить командой `pnpm dev:attacker`.

Если порт занят:

```powershell
$env:TALK_PORT = '3002'
$env:CSRF_ATTACKER_PORT = '3003'
pnpm dev
```

Для просмотра сборки: `pnpm build`, затем `pnpm --filter @ws/talk start`;
для CSRF также запустите `pnpm dev:attacker` в отдельном терминале.
Скрипты запуска слушают только локальный интерфейс: приложение содержит намеренные
учебные уязвимости.

## Что работает

Все 17 слайдов исходной презентации перенесены в JSON с сохранением порядка тем.
В XSS добавлены сравнение кода и живое демо. CSRF раскрывается в четырёх экранах:
суть уязвимости, другие меры защиты, код и демо
с переключением на `fixed`. Зависимости: суть, действия потребителя, обновление package.json, демо.
Итого 25 экранов, 15 модулей. Доступны содержание, кнопки листания,
клавиатурная навигация, заметки докладчика и полноэкранный режим.
Реализованы stored XSS в комментариях, CSRF при изменении адреса доставки и XSS внутри учебной зависимости.
Пошаговые сценарии: [XSS-демо](docs/demo/xss.md), [CSRF-демо](docs/demo/csrf.md),
[демо зависимости](docs/demo/dependencies.md).

Данные живут в памяти одного процесса Next.js и сбрасываются при его перезапуске.
Все вкладки используют общий список комментариев. Пользователь Алекс и его cookie
учебные; полноценной аутентификации пока нет. CSRF-профиль привязан к отдельной
случайной учебной сессии браузера с часовым сроком жизни. В `fixed` комментарии выводятся
как текст, а cookie получает `HttpOnly`. CSP допускает inline-скрипты для Next dev
и не является самостоятельной защитой от XSS в этом примере.

CSRF-защита проверяет случайный токен сессии на сервере до изменения адреса.
Акция работает с другого origin на том же site: это позволяет показать проверку
токена без отключения `SameSite=Lax`. Сервер акции не читает cookie.

Модуль зависимостей использует две локальные реализации вымышленной библиотеки
`product-description-renderer` для отображения описаний товаров: 1.0.0 вставляет HTML,
1.0.1 выводит текст. Это учебная модель
обновления, не установка реального уязвимого пакета. Описание хранится в состоянии
страницы и сбрасывается при перезагрузке. `pnpm audit` не обнаруживает эту локальную модель.

Остальные 9 тем представлены только теоретическими слайдами без запуска атак.
Оформление повторяет PPTX: белый фон, Arial, синие заголовки, оранжевые и бирюзовые
акценты. Логотип ЭТМ и изображение каталога извлечены из оригинала и находятся
в `apps/talk/public/presentation`.

## Код и материалы

| Каталог | Назначение |
| --- | --- |
| `apps/talk` | Next.js App Router: React-слайды, демо-сайт и серверные API |
| `apps/talk/src/features/vulnerabilities` | Папки 12 тем; уязвимая и исправленная реализации рядом |
| `packages/slides-schema` | Zod-схема, типы слайдов и CLI-валидация |
| `content/slides` | JSON-модули и их порядок в `index.json` |
| `docs/security-guide` | Дополнительные материалы прежнего доклада |

В приложении используется FSD и обёртки над Ant Design; общие UI-компоненты лежат
в `shared/ui`. Типы слайдов: `title`, `bullets`, `code`, `story`, `demo`, `checklist`,
`two-columns`, `timeline`, `agenda`, `vulnerability`. Поле `sourceSlide` связывает
слайд с оригиналом PPTX. Слайды `code` читают реальные файлы относительно
`apps/talk/src`. Новая тема добавляется JSON-модулем и записью в `index.json`;
демонстрация получает пару реализаций в `features/vulnerabilities/<name>` и страницу `/site/...`.
Карта папок и соглашения: [модули уязвимостей](apps/talk/src/features/vulnerabilities/README.md).

Стрелки, Space и Page Up/Down перелистывают слайды, F включает полный экран.
Enter открывает демо, Escape возвращает к слайду. Содержание и заметки доступны
через кнопки в шапке; при открытых панелях перелистывание слайдов приостановлено.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm validate:slides
pnpm build
pnpm --filter @ws/talk exec playwright install chromium
pnpm e2e
```

Playwright сам запускает локальный сервер или использует уже работающий на порту
3000 и сервер акции на 3001. Браузерные проверки сбрасывают данные сценариев.
Для другого сервера задайте `PLAYWRIGHT_BASE_URL`; для установленного Edge можно
задать `PLAYWRIGHT_CHANNEL=msedge`. При `PLAYWRIGHT_BASE_URL` оба сервера нужно
запустить самостоятельно с согласованным `CSRF_ATTACKER_PORT`.

Рабочий процесс: одна ветка на изменение в текущей папке, проверки и слияние в
`main`. Автор коммитов берётся из локальных настроек Git.
