# Prototype Pollution

Три экрана: `/talk/prototype-pollution/0` (суть), `/1` (фронтенд-код), `/2` (демо).
Магазин: `/site/catalog`. Дополнительный сервер для этой темы не требуется.

| Файл | Назначение |
| --- | --- |
| `merge-catalog-settings.ts` | Уязвимый рекурсивный merge: проходит по унаследованным объектам |
| `fixed-merge-catalog-settings.ts` | Zod .strict() на обоих уровнях, явное копирование разрешённых полей |
| `delivery-estimate.ts` | Независимый потребитель: читает опцию доставки у нового объекта |
| `catalog.worker.ts` | Настоящее загрязнение в отдельном JavaScript-контексте и наблюдения |
| `PrototypePollutionDemo.tsx` | Импорт JSON, предварительный расчёт и инспектор прототипа |
| `fixtures.ts` | Обычные настройки, два payload и тип результата |
| `settings.test.ts` | Атаки в изолированном Node.js VM-контексте и проверка схемы |

Только Worker импортирует уязвимое слияние. Перед каждым импортом, сменой режима и
сбросом UI создаёт новый Worker. После результата, ошибки, таймаута или ухода со страницы
он завершается. Данные возвращаются как собственные поля через structured clone,
прототип Worker не передаётся в React или серверный процесс.

Worker нужен для устойчивости стенда, это не показанное исправление уязвимости.
Исходный JSON ограничен 8000 символами и 20 уровнями вложенности в обоих режимах.
Предварительная стоимость меняется только в браузере; серверной цены и оплаты нет.
Расчёт доставки не получает импортированные настройки аргументом, но в уязвимом
контексте читает загрязнённый прототип. В fixed отклоняется весь неправильный импорт.

Смена режима повторяет последний применённый JSON в чистом контексте. Черновик
передаётся только по кнопке импорта. Сброс возвращает обычные настройки.
