# Сторонний чат поддержки

Слайды: `/talk/third-party-scripts/0`–`/3`. Демо: `/site/checkout`.

- `create-support-chat-script.ts`: наше уязвимое подключение готового чата.
- `fixed-create-support-chat-script.ts`: не создаёт script на checkout; чужой файл не меняем.
- `vendor/support-chat.js`: рабочий виджет с вопросом о доставке.
- `vendor/steal-checkout-fields.js`: добавленный атакующим код чтения и отправки полей заказа.
- `server.mjs`: исходный файл или исходный файл + вредоносное дополнение; локальный получатель.
- `CheckoutDemo.tsx`: общая форма, загрузка виджета и монитор фактических запросов.
- `demo-data.json`: единственные значения, разрешённые для записи; форма readOnly.
- `scripts.test.ts` / `server.test.ts`: подключение, состав выдаваемых файлов, валидация и изоляция записей.

Чат загружается при открытии страницы. Подменённый скрипт читает уже заполненную
форму, не дожидаясь оформления. В fixed вместо внешнего виджета обычная ссылка
на учебную почту поддержки. Оформление заказа работает в обоих режимах.

Внешний сервер отдаёт CORS-заголовок; script использует crossOrigin=anonymous,
получатель credentials=omit. CSP fixed-документа не разрешает внешний script-src,
но connect-src разрешает монитор учебного получателя. Меню перезагружает документ
при входе и выходе из checkout для применения заголовков.

Новый UUID создаётся при загрузке, смене файла, режима и сбросе. Проверка dataset.run
в vendor-коде отсекает устаревшие запуски после очистки, это не механизм защиты.
Получатель принимает только два учебных значения, максимум 500 записей на 10 минут;
проверяет UUID, лишние поля и лимит тела 2 КиБ. Cookie не читаются и не отправляются.
Сброс повторно запускает текущий сценарий; при подмене утечка повторяется.
Ранее отправленные данные не отменяются и хранятся до истечения срока.

Важно: удаление тега script не отменяет уже выполненный код. В production стороннюю
интеграцию подключают только в явно разрешённых layout, учитывая SPA-переходы.
В этом стенде чат существует только на одной странице, его эффекты ограничены
виджетом и одноразовым POST. SRI и iframe обсуждаются, но не реализованы.

Учебный сценарий по мотивам Ticketmaster / Inbenta, не точная реконструкция,
не платёжная форма и не готовая production-защита.
