# Сторонние скрипты / Magecart

Слайды: `/talk/third-party-scripts/0`–`/3`. Демо: `/site/checkout`.

- `create-analytics-script.ts` / `fixed-create-analytics-script.ts`: наше подключение без SRI и с ним.
- `integrity.ts`: закреплённый SHA-384 проверенной копии, не ответ текущего CDN.
- `vendor/checkout-analytics.js`: исходная аналитика, отмечает событие заказа без чтения полей.
- `vendor/compromised-checkout-analytics.js`: подменённая аналитика читает email и адрес и делает POST на локальный получатель.
- `CheckoutDemo.tsx`: общая форма, выбор файла CDN, выполнение и показ фактического ответа получателя.
- `server.mjs`: обработчик локального CDN и коллектора, подключается из `scripts/csrf-attacker.mjs`.
- `demo-data.json`: единственные значения, разрешённые для записи получателем; форма readOnly.
- `scripts.test.ts` / `server.test.ts`: параметры подключения, хеш выдаваемых байтов, изоляция и валидация коллектора.

Оба режима используют один и тот же файл выбранного варианта. Отличие — атрибут
`integrity`; чужой код в fixed не исправляем. В исходном варианте файл успешно
проходит SRI, в подменённом браузер отклоняет его до выполнения. Ошибка загрузки
может означать и сетевую проблему; UI не выдаёт каждый script.onerror за доказательство SRI.

CDN отдаёт CORS-заголовок, загрузка использует `crossOrigin=anonymous`, запросы
получателя — `credentials: omit`. CSP страницы разрешает этот локальный origin
для script-src и connect-src, чтобы блокировку нельзя было спутать с CSP.
Вход и выход через меню перезагружают документ для применения соответствующих заголовков.

Каждое оформление получает новый UUID. Получатель хранит до 500 записей, удаляет
просроченные через 10 минут при следующем запросе и отвергает неизвестные значения,
лишние поля, некорректный UUID и тело больше 2 КиБ. Сброс очищает текущий запуск UI,
но не удаляет чужие записи: они истекают сами. Смена режима перемонтирует демо;
удаление script не отменяет уже отправленный запрос, поэтому ID запусков не переиспользуются.

Сервер нормализует окончания строк vendor-файлов в LF перед отправкой. После
осознанного изменения доверенного файла нужно пересчитать SHA-384 и проверить
`server.test.ts`, который сопоставляет закреплённый хеш и реально выдаваемые байты.

Это локальный учебный стенд, не production-защита и не платёжная форма.
