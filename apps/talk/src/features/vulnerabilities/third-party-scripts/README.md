# Сторонние скрипты

Слайды: `/talk/third-party-scripts/0`–`/3`. Демо начинается на `/site`, затем `/site/checkout`.
Чат — пример сторонней интеграции. Тема включает также аналитику, рекламу и библиотеки с CDN.

- `create-support-chat-script.ts`: наше уязвимое подключение без проверки файла.
- `fixed-create-support-chat-script.ts`: то же подключение с обязательным SRI, без проверки pathname.
- `integrity.ts`: закреплённый SHA-384 проверенного `vendor/support-chat.js` с окончаниями LF.
- `vendor/support-chat.js`: исходный рабочий чат с вопросом о доставке.
- `vendor/steal-customer-data.js`: добавленный код отправки учебных данных покупателя.
- `server.mjs`: исходный файл или исходный + вредоносное дополнение; локальный получатель.
- `ThirdPartyScriptsDemo.tsx`: одна интеграция для главной и заказа, монитор фактических запросов.
- `demo-data.json`: единственные значения, разрешённые получателем; форма readOnly.
- `scripts.test.ts` / `server.test.ts`: обязательный integrity, хеш реально выдаваемых байтов, валидация получателя.

Чат загружается при открытии любой из двух страниц. Уязвимый скрипт отправляет
предзаполненные поля уже на главной. Fixed не пытается отключить его на следующей
странице: до каждого выполнения браузер сравнивает файл с закреплённым хешем.
Исходный файл совпадает и работает, подменённый блокируется до чтения данных.
Хеш не вычисляется из текущего ответа поставщика. При изменении проверенной версии
нужно осознанно пересчитать SHA-384 по LF-байтам и проверить тест сервера.

Сервер разрешает CORS, оба script используют crossOrigin=anonymous; получатель —
credentials=omit. CSP fixed-документа на главной и в заказе разрешает локальный сервер
для script-src/connect-src, чтобы тест проверял SRI, а не блокировку домена.
Браузерные тесты проверяют именно сообщение о несовпадении хеша и успешный запуск
исходного файла. script.onerror сам по себе может означать и сетевую ошибку.

При смене режима перезагружается документ. Это новая защищённая загрузка,
не обезвреживание уже исполненного кода. Переходы через меню на страницы демо
и обратно также загружают документ заново для применения CSP.

Новый UUID создаётся при загрузке, смене варианта и сбросе. dataset.run отсекает
устаревший запуск после очистки стенда, не защищает от кражи данных. Получатель
принимает только два учебных значения, максимум 500 записей на 10 минут; проверяет
UUID, лишние поля и лимит тела 2 КиБ. Cookie не читаются и не отправляются.
Сброс повторяет сценарий; старые утечки не отменяются и истекают самостоятельно.

SRI не анализирует поведение, не защищает автоматически вложенные скрипты и не
помогает, если одобрен вредоносный файл или атакующий меняет HTML/ожидаемый хеш.
Автообновляемые интеграции требуют контроля версий либо другой архитектуры.
Изоляция iframe обсуждается, но не реализована. CSP совместима с Next dev,
это учебный стенд, а не готовая production-конфигурация.
