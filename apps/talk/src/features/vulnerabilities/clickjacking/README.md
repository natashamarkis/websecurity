# Clickjacking

Три экрана: `/talk/clickjacking/0` (суть), `/1` (код), `/2` (демо).
Магазин: `/site/notifications`. Приманка: порт 3001, `/clickjacking?shopPort=3000`.

| Файл | Назначение |
| --- | --- |
| `get-frame-headers.ts` | Бэкенд: нет запрета на iframe |
| `fixed-get-frame-headers.ts` | Бэкенд: CSP frame-ancestors и X-Frame-Options |
| `ClickjackingDemo.tsx` | Профиль и письмо с приманкой |
| `session.ts` | Отдельная учебная сессия, настройка и CSRF-проверка |
| `notification-page.ts` | Настоящая HTML-форма магазина, работает и напрямую |
| `attacker.html` | Страница акции и раскрытие скрытого слоя без JavaScript |
| `attack-layer.html` | Реальный прозрачный iframe поверх кнопки-приманки |
| `notifications.test.ts` | Проверки сессии, токена, Origin, сброса и заголовков |

Общий `proxy` применяет выбранную пару заголовков ко всем `/site/*` через
`shared/lib/security-headers.ts`, сохраняя остальные директивы CSP. Сам POST
в обоих режимах требует сессию, допустимый Origin и её CSRF-токен.
Это Clickjacking, а не незащищённый от CSRF endpoint: жертва нажимает настоящую форму.

Кнопка «Сбросить» включает уведомления только в текущей сессии. Сессии живут час
в памяти процесса; магазин ничего не рассылает. Сервер акции игнорирует cookie,
не читает DOM iframe и не делает запросов во внешний интернет.
Смена режима не закрывает старые вкладки: для проверки заголовков предложение
нужно открыть заново. Сценарий докладчика: [clickjacking.md](../../../../../../../docs/demo/clickjacking.md).
