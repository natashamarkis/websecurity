# Brute Force и Credential Stuffing

Начало: `/talk/brute-force/0`. Демо: `/site/backend/brute-force`.

## Сценарий доклада

Основа: Cybersecurity.pptx, слайд 15. Нажмите «Проверить список». В vulnerable шестой пароль Cable2026! даёт 200 после пяти 401. После переключения на fixed счётчик начинается с нуля: три 401, затем 429 даже для правильного шестого пароля. UI отправляет отдельный HTTP-запрос на каждый пароль, максимум восемь, без внешних целей. Сбросьте и введите Cable2026! вручную: штатный вход работает. Список и правильный пароль учебные. Сравнение выполняется по scrypt-хешу через timingSafeEqual. Временный лимит не полная защита от credential stuffing: верный пароль с первой попытки пройдёт, нужна MFA и дополнительные сигналы. В стенде счётчик хранится в памяти одного процесса и привязан к копии аккаунта зрителя, общей для его вкладок. В production счётчик должен быть атомарным и общим для всех инстансов, привязанным к нормализованному account ID независимо от cookie. Кнопка сброса и переключатель режима предназначены только для лаборатории, их не должно быть в production.

## Общие границы лаборатории

- Только вымышленные данные. Не вводить реальные пароли, токены и адреса.
- Cookie `backend-lab` отделяет одну копию сценария от другой. Это инфраструктура стенда.
- Cookie `demo-mode` выбирает серверную реализацию. Параметр режима из JSON не принимается.
- Состояние существует до часа, максимум 200 активных копий на процесс. Перезапуск очищает его.
- При переключении режима и сбросе сервер начинает чистый сценарий. Ввод формы сохраняется для сравнения.
- Управляющие POST не принимают чужой Origin. JSON ограничен 4096 байтами.
- Кнопки сброса и выбора уязвимого режима не предназначены для production.
