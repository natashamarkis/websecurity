# Сторонняя аналитика и SRI

Запуск обоих серверов: `pnpm dev`. Магазин: `127.0.0.1:3000`, CDN и получатель:
`127.0.0.1:3001`. Другие порты задаются через `TALK_PORT` и `CSRF_ATTACKER_PORT`.
Все обращения остаются локальными; никаких реальных персональных или платёжных данных.

## Сценарий

1. `/talk/third-party-scripts/0`: подключаем checkout-analytics.js ради аналитики заказов, но внешний src не изолирует код от DOM магазина.
2. `/1`: SRI сравнивает загруженные байты с хешем заранее проверенной копии, не анализирует поведение.
3. `/2`: сверху наше подключение, снизу подменённый чужой скрипт. В fixed меняется только наше подключение — добавляется integrity. Чужой файл остаётся таким же.
4. `/3`: открыть демо, оставить «Подменённый», нажать «Оформить заказ». Справа появляется событие и полученные email и адрес.
5. Переключить на «Исправлено», снова оформить. Подменённый файл не выполняется, события и новых данных нет.
6. Выбрать «Исходный» и повторить. SRI пропускает проверенную аналитику: событие есть, утечки полей нет.
7. Сбросить текущий запуск; вернуться к слайду через Escape или кнопку.

Полезно открыть Network: без SRI есть POST `/third-party/collect`, с SRI при
подмене его нет. Console показывает несовпадение integrity. Общая ошибка загрузки
в интерфейсе может быть вызвана также недоступностью CDN, это не самостоятельное
доказательство срабатывания SRI. Браузерные тесты проверяют точную причину и положительный контроль.

## Ограничения

Хеш закреплён в нашем репозитории по доверенному `vendor/checkout-analytics.js`.
Не получаем его из текущего ответа CDN. При легитимном обновлении сначала проверяем
новый файл, затем меняем хеш. CDN должен разрешать CORS, а script использует anonymous.

CSP только на checkout разрешает локальный CDN/получатель для чистоты эксперимента.
В production connect-src и другие директивы дополняют защиту. Разрешение домена в
script-src не гарантирует неизменность файла на нём. SRI не помогает, если заранее
закрепить хеш вредоносного кода или атакующий может изменить и HTML с integrity.

Форма содержит фиксированные вымышленные значения; получатель принимает только их,
не читает cookie, изолирует записи по UUID и ограничивает память/время хранения.
Смена режима и сброс создают новый контекст: старый POST, уже отправленный до защиты,
не становится «отменённым». UI показывает только данные текущего запуска.

Источники: [MDN: SRI](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity),
[MDN: script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src).
