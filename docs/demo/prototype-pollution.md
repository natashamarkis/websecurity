# Prototype Pollution

Запуск: `pnpm dev`. Открыть `/talk/prototype-pollution/0`.
Для этого модуля достаточно основного Next.js-сервера.

## Сценарий

1. На первом слайде объяснить цепочку: недоверенный JSON, рекурсивное слияние,
   общий прототип, чтение значения другим объектом.
2. На `/1` показать строку `target[key] ??= {}`. Для `__proto__` значение уже есть:
   это `Object.prototype`. Рекурсивный вызов записывает данные прямо туда.
3. Во вкладке «Исправлено» показать строгую схему на каждом уровне. После успешной
   проверки копируются только `view.sort` и `view.pageSize`.
4. `/2`: открыть каталог. Обычные настройки импортированы, доставка 490 ₽.
   У прототипа и нового объекта `deliveryFee` отсутствует.
5. Выбрать `Payload: __proto__`, нажать «Импортировать настройки».
   После JSON.parse всё ещё undefined; после merge значение прототипа равно 0.
   Новый `{}` читает 0, хотя `Object.hasOwn` возвращает false. Доставка стала 0 ₽.
6. Переключить «Исправлено». Тот же применённый JSON отклонён, прототип чист,
   предварительная стоимость 490 ₽. Чистый запуск обеспечивает новый Worker.
7. Проверить `constructor.prototype`: это второй путь к тому же прототипу.
   Обе атаки отклоняются схемой, а не только проверкой одного слова `__proto__`.
8. Выбрать обычный JSON и импортировать его в fixed: сортировка и размер страницы
   применяются. Некорректный JSON и неверные типы показывают ошибку.
9. «Сбросить» возвращает обычные настройки. Escape возвращает на тот же слайд.

## Что на самом деле произошло

`JSON.parse` сам по себе не загрязняет прототип. Ключ `__proto__` становится
обычным собственным полем прочитанного объекта. Ошибка возникает, когда наш merge
использует его для перехода в существующий прототип целевого объекта.

Для самостоятельного расчёта создаётся `const deliveryOptions = {}`. Расчёт читает
`deliveryOptions.deliveryFee ?? 490`. Собственного поля нет, но прототип содержит 0.
Оператор `??` не заменяет 0 значением 490: 0 не равен null или undefined.
Настройки каталога не передавались в расчёт доставки.

Это подмена предварительной цифры в интерфейсе, не получение бесплатного заказа.
Настоящий сервер должен сам рассчитывать цену. Аналогично появление `isAdmin` на
фронтенде не создаёт серверных прав. XSS или обход проверок требуют дополнительного
кода, который небезопасно использует унаследованное значение.

## Изоляция и защита

Пример действительно меняет Object.prototype, но внутри одноразового Web Worker.
В том же Worker выполняется расчёт доставки. React получает только результаты;
его прототип, сервер и другие вкладки не загрязняются.
Worker завершается после результата, при смене режима, уходе, ошибке или таймауте.
Длина JSON и глубина ограничены в обоих режимах для устойчивости стенда.

Изоляция не является исправлением импорта. Исправление находится в соседнем файле:
строгая Zod-схема и явное копирование двух известных полей. Отказ происходит до записи.
Новый Worker при переключении демонстрирует чистый повторный запуск, а не удаление
загрязнения из уже работающего приложения. В реальном процессе исправление источника
само по себе не отменяет сделанные ранее изменения прототипа.
