# Stored XSS в комментариях

Запуск: `pnpm dev`, теория <http://127.0.0.1:3000/talk/xss/0>,
разбор кода <http://127.0.0.1:3000/talk/xss/1>,
демонстрация <http://127.0.0.1:3000/talk/xss/2>.

1. Нажмите «Открыть демонстрацию» или Enter. Откроется `/site/comments` в режиме «Уязвимо».
2. Вставьте в комментарий:

   ```html
   <img src=x onerror=alert(document.cookie)>
   ```

3. Нажмите «Отправить». Выполнится JavaScript, в окне появится учебная cookie
   `session=sess_alex_7f3a9c`. Закройте окно.
4. Перезагрузите страницу: payload сохранён в памяти сервера и выполнится снова.
5. Переключитесь на «Исправлено». Тот же комментарий отображается текстом.
   Рендер больше не создаёт HTML из ввода, а `session` скрыта от JS флагом `HttpOnly`.
6. Нажмите кнопку сброса в панели демо, чтобы вернуть два исходных комментария.
7. Escape или «К слайду» возвращает к исходному слайду доклада.

Реализации для разбора находятся в
`apps/talk/src/features/vulnerabilities/xss/XssInject.tsx` и `FixedXssInject.tsx`.
Комментарии общие для всех вкладок и не сохраняются после перезапуска сервера.

Перед демонстрацией слайд `/talk/xss/1` показывает эти файлы во вкладках
«Уязвимо» и «Исправлено». Уязвимость и исправление показываем в одном демо,
переключая режим без возврата к слайдам. После возврата следующая тема: CSRF.

CSRF ещё не реализован. Для него нужен отдельный сценарий и origin; выполнение
запроса из внедрённого на этом же сайте JavaScript само по себе не демонстрирует CSRF.
