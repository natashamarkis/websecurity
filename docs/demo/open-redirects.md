# Open Redirect

Запуск: `pnpm dev`. Магазин по умолчанию на 3000, учебный внешний сайт на 3001.
Порты настраиваются через `TALK_PORT` и `CSRF_ATTACKER_PORT`.

## Сценарий

1. `/talk/open-redirects/0`: объяснить класс угроз. Пользователь видит доверенный
   адрес магазина, а параметр next задаёт непроверенное назначение.
2. `/1`: показать две функции фронтенда. Fixed проверяет разобранный origin
   перед window.location.assign. Обработка на сервере потребовала бы такой же
   проверки перед формированием Location.
3. `/2`: открыть письмо. Ссылка действительно начинается с origin магазина;
   next содержит другой локальный origin. Нажать «Посмотреть заказ».
4. Браузер проходит через `/site/redirect/go` и оказывается на порту 3001.
   Внешняя страница предлагает войти, но учебный стенд не запрашивает данные.
5. Вернуться к письму ссылкой, переключить «Исправлено» и повторить переход.
   Браузер остаётся в магазине: «Переход заблокирован».
6. Повторить с вариантом «Адрес без протокола //»: fixed также отклоняет его.
7. Выбрать «Заказ внутри магазина»: переход открывает заказ в обоих режимах.
8. Сбросить письмо и вернуться к слайду через Escape или кнопку.

## Что важно проговорить

Open Redirect не крадёт пароль автоматически. Он позволяет использовать доверенный
домен как промежуточный адрес для фишинга; дальнейший ввод на чужом сайте — отдельный шаг.
Не обещаем, что same-origin делает безопасными все внутренние страницы и цепочки
перенаправлений. Для чувствительных действий лучше явный список назначений.
Проверки строкового префикса недостаточно: `//host` и `user@host` разбираются как URL.

Стандартный парсер query декодирует значение один раз. Затем new URL выполняет
нормализацию; сравнение включает протокол, хост и порт. Без дополнительных decode
используется тот же нормализованный href, который прошёл проверку.

Оболочка демо в обоих режимах отдельно ограничивает переходы двумя подготовленными
локальными страницами. Это ограничение учебного стенда, а не исправление на слайде.
Сервер 3001 не принимает формы и не читает cookie. Это разные origin, но один хост:
cookie портом не изолируются. Логины, пароли и платежи не используются.
